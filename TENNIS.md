# Tennis discovery board

The Tennis tab retrieves ATP/WTA singles schedules and set scores from ESPN website JSON, and open Kalshi KXATPGTOTAL / KXWTAGTOTAL full-match completed-games contracts. Tennis collection runs separately after basketball collection in the scheduled workflow. Matching requires both normalized player names, the tour, and the contract's scheduled day; ambiguous matches remain unassigned. Doubles are excluded. A tournament feed can include a whole draw, so competition-level dates are filtered to a three-day window.

Initial collection 2026-11-05T09:55:42.492899Z: 53 open total-games contracts, 45 matched. No invented prices, model probabilities, simulated runs or paper positions are displayed. Quoted market bid/ask fields are not verified executable depth.

This is not a completed tennis prediction engine. The inspected live responses lack current point scores and verified serve statistics. Some include generic possession/situation fields whose tennis meaning is unverified. The feed reports five regulation periods for some ATP Paris matches despite completed two-set matches, so that field is not accepted as verified format. Set-only state does not establish current server, point score, injury/retirement status, surface-adjusted serve probabilities or tiebreak format.

ESPN's undocumented website endpoints have no established redistribution license, latency SLA, or published rate contract here. Sportradar Tennis v3 Live Summaries/Timelines were investigated and provide richer state by coverage level, but no authenticated provider access has been supplied or connected. See https://developer.sportradar.com/tennis/docs/tennis-ig-live-match-retrieval and https://developer.sportradar.com/tennis/docs/tennis-ig-update-frequencies.

Kalshi's inspected total-games rules distinguish completed games from points and sets. Injury, retirement, walkover and postponement treatment is shown verbatim per contract. Some retirement outcomes resolve at fair price rather than a simple binary settlement. No tennis paper entries are made until a separate tennis scoring model, trustworthy inputs and applicable settlement handling are verified. Existing basketball forecasts/ledgers remain unchanged.

Esports is explained in the tab, but no esports model or live gameplay feed is connected. A total-maps series market is a different quantity from kills, rounds, points or duration. No claim is made that all esports titles score slowly.

## Player picker and independent engine (November 5 update)

The live player picker now supports manual entry of completed sets, current set games, current point score, current server, best-of-three/five format, a 7- or 10-point deciding-set tiebreak, and both players' service points won/played. Required fields start blank where the feed cannot verify them. Standard advantage games/tiebreak sets only; doubles, no-ad, advantage final sets and replacement match tiebreaks are rejected or unsupported.

An actual seeded 10,000-run point-by-point Monte Carlo engine returns match, current-set and next-game winner probabilities; total/remaining games; mean, median and 10th–90th range; and conditional probabilities for supported matched Kalshi contracts. Tiebreak serving order and the next set's opening server are modeled. Current-match service-point evidence implicitly reflects the opponent's returning; surface-adjusted historical player ability is not connected. Uncalibrated priors: ATP .64 or WTA .60 service-point win probability, 80 pseudo-points per player. Each simulation draws a service probability from the beta posterior; no market prices enter either probabilities or the random seed. No confidence or profitability claim follows from completing 10,000 runs.

Manual analyses save only in that browser's localStorage, clearly labeled manual/unverified and excluded from the shared paper win/loss record. Copying the analysis record is available. Capture/source verification and actual executable prices are not established by typing a source name. The UI shows conditional game-total/match-winner probabilities, with no verified betting edge or EV claim.

The optional backend adapter uses official Sportradar Tennis v3 Live Summaries with `x-api-key` read from a GitHub Actions secret named SPORTRADAR_TENNIS_API_KEY. The optional repository variable SPORTRADAR_TENNIS_ACCESS_LEVEL selects trial or production; default trial. No credentials are placed in public files or browser storage. The adapter checks live coverage, player identity, current set/point/server state, serving-point counts, response timestamp and supported scoring presets. Automatic mode currently accepts standard best-of-three ATP 250/500/1000 and listed WTA tour singles levels, using standard 7-point tiebreak sets; other events are blocked for separate rule verification. It has schema/unit tests but has not been verified against an authenticated live account because provider access has not been supplied.

When a valid provider state is available, automatic experimental forecasts append to data/tennis_forecasts.jsonl; normal completed-match score grades append separately to data/tennis_grades.jsonl. Retirements/walkovers/abandonments are excluded from this normal-completion grading. These are scoring/player forecasts, not automatically executed tennis paper bets. Tennis settlement/fill-aware paper returns remain unimplemented and are not reported as completed.

Official scoring references: https://www.itftennis.com/media/7221/2026-rules-of-tennis-english.pdf and https://www.itftennis.com/media/15604/atp-2026-rulebook.pdf. Provider schema references: https://developer.sportradar.com/tennis/reference/live-summaries and https://developer.sportradar.com/tennis/docs/tennis-ig-live-match-retrieval. These documentation examples are not used as live match data.

## API Tennis connection
The collector reads API_TENNIS_KEY only from the GitHub Actions secret. REST live responses enrich uniquely matched ATP/WTA singles with serving identity, point score, set scores, and returned statistics. No key or authenticated URL is saved. Source-origin timestamps and format are not supplied by this adapter; automatic recommendations remain blocked. GitHub scheduled snapshots are not a continuous point-level stream.

## Automatic forecasts, November 5 update
API Tennis live and fixture responses now drive the engine automatically. Both players' match Service Points Won count is used; first- and second-serve counts are summed only if the overall count is absent. Missing serving samples use explicitly labeled league priors. Server and current point score must be present; inconsistent set transitions wait for the next capture. Tour singles use ATP/WTA best-of-three advantage-game tiebreak rules. Grand Slam main-draw presets use a 10-point deciding tiebreak (men best of five, women best of three); special events and Slam qualifying need separate presets.

Predictions are conditional on the captured state and normal completion. Source-origin delay is not supplied by this provider. The engine does not claim to remove this uncertainty. Live order-book bid complements supply one-contract executable asks/VWAP and available size. Applicable quadratic series fees are fetched; unknown fee types leave net EV unavailable. Conditional model value does not establish a verified edge. GitHub runs nominally every five minutes and can be delayed; browser refresh does not make an old snapshot current.

Forward forecasts are immutable JSONL and grade into a separate file using completed set evidence. No trades, assumed fills, retrospective forecasts, or paper profits are created. The picker pre-fills automatically sourced model inputs for review.
